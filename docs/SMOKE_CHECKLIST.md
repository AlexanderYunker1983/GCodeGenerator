# Ручной прогон GCodeGenerator

Проверка живой программы перед выпуском и после изменений, видимых пользователю.

**Что здесь проверяется.** Только то, чего не видят автоматические тесты: как
выглядит и ведёт себя окно, что происходит при установке, читаются ли надписи
на обоих языках, перерисовывается ли предпросмотр. Всё, что можно проверить
без человека, уже проверено — генерация, форматы, разбор чертежей, файл проекта
и эталонные программы покрыты автотестами (см. «Что покрыто автоматикой» в
конце). Дублировать их руками не нужно: сверять G-код построчно глазами здесь
не требуется ни в одном пункте.

**Когда прогонять**

- перед выпуском версии — целиком;
- после изменения, видимого пользователю (диалоги, список операций, предпросмотр,
  настройки, установщик) — затронутые разделы.

## Подготовка

```powershell
dotnet build GCodeGenerator.sln -c Release
```

Запуск: `GCodeGenerator\bin\Release\GCodeGenerator.exe`

Что понадобится:

- чертежи для импорта — `GCodeGenerator.Core.Tests\Assets\`: `profile_sample.dxf`,
  `pocket_sample.dxf`, `circle_sample.dxf`, `lwpolyline_sample.dxf`;
- любой не-DXF файл, переименованный в `.dxf`, — для проверки сообщения об ошибке;
- эталонный проект `GCodeGenerator.Core.Tests\Reference\reference_project.ygc`
  (19 операций всех типов) — им удобно проверять открытие и предпросмотр, не
  создавая операции вручную.

Отметка: `[x]` — в порядке, `[!]` — есть замечание (записать в журнал внизу).

## A. Операции и диалоги

- [ ] **A1.** Все 19 диалогов открываются: 9 видов сверления (точки, линия, массив,
      прямоугольник, окружность, дуга, многоугольник, эллипс, пакет), 6 профилей
      (прямоугольник, скруглённый прямоугольник, окружность, эллипс, многоугольник,
      DXF), 4 кармана (прямоугольник, окружность, эллипс, DXF).
      *Ожидается: для каждого вида — свой диалог, операция появляется в списке
      с описанием.*
- [ ] **A2.** Двойной щелчок по операции в списке открывает диалог **её** вида.
- [ ] **A3.** Отмена диалога не меняет операцию; повторное открытие показывает
      прежние значения.
- [ ] **A4.** Неверный параметр (например, нулевая глубина): OK не закрывает окно,
      под кнопками появляется перечень проблем, поле подсвечено.
- [ ] **A5.** Поля с числами принимают запятую и точку, не пропускают буквы.

## B. Список операций, отмена и повтор

- [ ] **B1.** Перемещение вверх/вниз, удаление, включение и отключение операции.
      *Ожидается: порядок в списке совпадает с порядком в G-коде; отключённая
      операция в программу не попадает.*
- [ ] **B2.** Ctrl+Z и Ctrl+Y отменяют и повторяют добавление, удаление,
      перемещение и правку параметров.
      *Ожидается: правка через диалог отменяется одним шагом, а не по параметру.*
- [ ] **B3.** Переименование операции сохраняется и видно в комментарии G-кода.

## C. Двумерный предпросмотр

- [ ] **C1.** Масштаб колесом, панорама перетаскиванием, «Показать всё».
- [ ] **C2.** Наведение подсвечивает операцию, щелчок выбирает её в списке,
      двойной щелчок открывает её диалог.
- [ ] **C3.** Переключение «контуры операций ↔ траектория инструмента»: на
      траектории видны проходы выборки и холостые переходы штрихом.
- [ ] **C4.** Кнопка «Показать всё» и флажок траектории не наезжают друг на друга
      ни на русском, ни на английском.

## D. Трёхмерный предпросмотр

- [ ] **D1.** Открывается, траектория видна целиком, вращение и масштаб работают.
- [ ] **D2.** Сетки XY, XZ, YZ включаются независимо, подписи читаются, шаг
      разумный для размеров траектории.
- [ ] **D3.** Диапазон примитивов: оба ползунка ограничивают показ, подпись
      называет номера и типы крайних элементов.
- [ ] **D4.** Перемещение ползунка **не** сбрасывает поворот и масштаб камеры;
      автокадрирование срабатывает только при открытии новой траектории.
- [ ] **D5.** Элементы управления внизу не перехватываются вращением сцены.

## E. Генерация и сохранение G-кода

- [ ] **E1.** Генерация большого проекта (эталонный подойдёт): окно не замирает,
      виден ход выполнения.
- [ ] **E2.** Правка операции во время генерации отменяет её без сообщения об ошибке.
- [ ] **E3.** Сохранение `.nc`: файл открывается в текстовом редакторе, кодировка
      без метки в начале, первая строка — комментарий программы.
- [ ] **E4.** Операция с неверными параметрами (открыть проект, поправив файл
      вручную): генерация отказывает с понятным сообщением, а не молча.

## F. Карманы

- [ ] **F1.** Все пять стратегий на одном кармане: спираль, концентрические,
      радиальные, зигзаг, линии. *Ожидается: траектория заполняет карман, проходы
      не выходят за контур.*
- [ ] **F2.** Направление обработки «из центра» и «снаружи внутрь» для спирали
      и концентрических: порядок проходов виден в 3D по диапазону примитивов.
- [ ] **F3.** Черновая с припуском и чистовая в трёх режимах (стенки, дно, всё).
- [ ] **F4.** Остров: карман с операцией-островом внутри. *Ожидается: остров
      не обрабатывается сам по себе, проходы его обходят, переходы через
      безопасную высоту.*
- [ ] **F5.** Винтовой вход: угол и диаметр видны только при нём; слишком большой
      диаметр для узкого кармана даёт понятное сообщение, а не сбой.
- [ ] **F6.** **Врезание.** В 3D пройти диапазоном примитивов по началу каждого
      реза: спуск в материал идёт рабочей подачей, быстрый ход останавливается
      на верху слоя. *Автоматика это проверяет (`PocketLayerEntryTests`), здесь —
      взгляд на форму траектории.*

## G. Импорт DXF

- [ ] **G1.** Профиль из `profile_sample.dxf`, карман из `pocket_sample.dxf`.
- [ ] **G2.** `circle_sample.dxf` и `lwpolyline_sample.dxf`: окружности и полилинии
      с дуговыми сегментами приходят целиком, без потерянных вершин.
- [ ] **G3.** Чертёж без подходящей геометрии — сообщение «контуров нет», операция
      не создаётся.
- [ ] **G4.** Не-DXF файл с расширением `.dxf` — сообщение об ошибке, программа
      продолжает работу.
- [ ] **G5.** Импорт большого чертежа не замораживает окно.

## H. Файл проекта

- [ ] **H1.** Сохранить → закрыть → открыть: операции, их порядок, параметры и
      настройки генерации на месте.
- [ ] **H2.** «Сохранить» второй раз пишет в тот же файл без вопроса;
      «Сохранить как» спрашивает имя всегда.
- [ ] **H3.** Заголовок окна: имя файла, звёздочка при несохранённых изменениях,
      название и версия программы.
- [ ] **H4.** Закрытие программы с несохранёнными изменениями спрашивает о
      сохранении; отказ от сохранения не закрывает программу, если нажать «Отмена».
- [ ] **H5.** Открытие повреждённого `.ygc` (испортить файл в редакторе):
      сообщение об ошибке, открытый проект остаётся нетронутым.
- [ ] **H6.** При уже открытом приложении дважды щёлкнуть другой `.ygc` в
      проводнике. *Ожидается: второго окна и второго процесса не остаётся,
      первое окно выходит на передний план и спрашивает о несохранённых
      изменениях перед открытием переданного проекта.*

## I. Настройки и стойка

- [ ] **I1.** Переключатели формата (номера строк, двузначные G-коды, дуги)
      меняют вывод в предпросмотре G-кода.
- [ ] **I2.** Выбор стойки: Generic и GRBL / LinuxCNC. *Ожидается: пауза после
      пуска шпинделя выводится в миллисекундах для Generic и в секундах для GRBL.*
- [ ] **I3.** Шпиндель (M3/M4/M5, обороты, задержка) и СОЖ (M8/M9) отражаются
      в программе.
- [ ] **I4.** «Сделать умолчаниями» запоминает настройки для новых проектов;
      открытие чужого проекта подставляет его настройки, а не умолчания.
- [ ] **I5.** Система координат G54–G59 и начальная точка G92.
- [ ] **I6.** Включить локальный профиль станка, задать узкие пределы X/Y/Z,
      подач и оборотов. Траектория внутри границ генерируется, выход за каждую
      границу блокируется с именем операции. Закрыть и снова открыть программу:
      профиль сохранился; открыть чужой `.ygc`: профиль не изменился.

## J. Безопасные высоты

- [ ] **J1.** Задать высоту контура выше безопасной высоты: ошибка появляется
      у поля безопасной высоты и снимается правкой любой из двух.
- [ ] **J2.** Сверление с приподнятой поверхностью: названы обе высоты — переход
      между отверстиями и отвод внутри отверстия.
- [ ] **J3.** Сообщения об этих ошибках читаются на русском и на английском.

## K. Язык и оформление

- [ ] **K1.** Переключение языка применяется сразу, без перезапуска; заголовок
      окна тоже меняется.
- [ ] **K2.** Светлая и тёмная темы: переключение без артефактов, оба
      предпросмотра перерисовываются.
- [ ] **K3.** Ни одна надпись не обрезана и не вылезает за элемент — на обоих
      языках.
- [ ] **K4.** Окно разворачивается и сжимается до минимального размера без
      наложения элементов; проверить при масштабе экрана 100 % и 150 %.
- [ ] **K5.** **Проверка обновлений.** В настройках она выключена. Нажать
      «Проверить сейчас» в окне «О программе» (F1). *Ожидается: ответ о том,
      что версия последняя, либо строка с номером вышедшей версии и кнопка
      перехода на её страницу.* Отключить сеть и нажать снова: *ожидается
      названная причина отказа в самом окне, а не отсылка к журналу; окно
      работает дальше.*
- [ ] **K6.** Кнопки «?» и «настройки» на панели одного размера.

## L. Установка

Проверяется на собранном установщике (`build\Make-Installer.ps1`), лучше — на
чистой системе или в виртуальной машине.

- [ ] **L1.** Установка на систему без .NET: программа запускается (сборка
      self-contained).
- [ ] **L2.** Мастер идёт на языке системы; ярлыки создаются, программа
      запускается по завершении.
- [ ] **L3.** **Установка только для себя.** Выбрать этот режим на первой
      странице мастера. *Ожидается: повышения прав не запрашивается, программа
      попадает в `%LOCALAPPDATA%\Programs`, ярлык и связь с `.ygc` работают,
      а в списке установленных программ она видна только у этого пользователя.*
- [ ] **L4.** **Установка для всех пользователей.** *Ожидается: запрос
      повышения прав, каталог в `Program Files`.* Повторный запуск установщика
      после этого вопроса о режиме не задаёт.
- [ ] **L5.** **Обновление поверх работающей программы.** Открыть проект, внести
      изменение, не сохранять, запустить установщик той же или новой версии.
      *Ожидается: установщик просит закрыть программу, она спрашивает о
      сохранении; ответ «Отмена» оставляет её работать, установщик предлагает
      завершить принудительно и предупреждает о потере изменений.*
- [ ] **L6.** Удаление убирает программу и ярлыки; журнал и настройки в
      `%LOCALAPPDATA%` остаются.
- [ ] **L7.** Свойства файла: издатель, описание, версия и правообладатель на
      месте — у установщика и у `GCodeGenerator.exe`.
- [ ] **L8.** Установить последний опубликованный выпуск, сохранить язык, тему,
      профиль станка и проект, затем установить кандидат поверх него.
      *Ожидается: программа запускается, настройки и проект читаются, одна запись
      в списке программ и связь `.ygc` указывают на новую версию.*
- [ ] **L9.** Для подписанного кандидата открыть «Цифровые подписи» у
      установщика, установленного/portable `GCodeGenerator.exe` и
      `unins000.exe`: везде один ожидаемый издатель, подпись действительна,
      метка времени присутствует.

## M. Журнал и восстановление после сбоя

- [ ] **M1.** `%LOCALAPPDATA%\GCodeGenerator\logs\gcodegenerator.log` пополняется:
      открытие и сохранение проектов, генерация, импорт.
- [ ] **M2.** Настройки переживают обновление версии (проверяется вместе с L3):
      язык, тема и умолчания генерации остаются прежними.
- [ ] **M3.** Создать операцию, не сохранять проект, подождать не меньше двух
      секунд и завершить процесс через диспетчер задач. При следующем запуске
      согласиться на восстановление: операция открылась в безымянном документе
      со звёздочкой, а Ctrl+S предлагает выбрать новый файл.
- [ ] **M4.** Повторить M3 и отказаться от восстановления. После следующего
      запуска предложение не появляется; `autosave.ygc` и его `.bak` удалены.

## Что покрыто автоматикой

Эти вещи проверяются на каждой сборке, руками их повторять не нужно:

- **Состав и текст программы** — golden-эталоны на все виды операций, стратегии
  и настройки формата (`GoldenTests`), эталонный проект из 19 операций через
  полный путь «файл проекта → G-код» (`ReferenceProjectTests`).
- **Безопасность траектории** — врезание только рабочей подачей
  (`PocketLayerEntryTests`), возврат сверла в отверстие с зазором
  (`DrillPeckReturnTests`), безопасный пролог программы (`SafetyPreambleTests`),
  проверка высот (`SafeHeightValidationTests`).
- **Проверка параметров** — все операции и настройки (`OperationValidationTests`,
  `FullValidationTests`), привязка ошибок к полям (`FieldErrorTests`), нижний и верхний
  пределы подач и оборотов (`SettingsValidationTests`).
- **Файл проекта** — запись и чтение всех поддерживаемых версий формата,
  отказ на повреждённых файлах (`ProjectFileServiceTests`).
- **Разбор чертежей** — сущности, блоки, единицы, восстановление замкнутых
  контуров (`Dxf*Tests`).
- **Локализация** — совпадение наборов ключей на обоих языках и наличие
  перевода для каждого кода проверки (`LocalizationTests`), причина отказа
  генерации на языке интерфейса (`CoreErrorMessagesTests`).
- **Предпросмотр** — построение сцены в фоне и показ причины, если оно
  не удалось (`ScenePreviewAsyncTests`).
- **Сборка и выпуск** — замок пакетов и закреплённый режим публикации
  (`PackageLockTests`), правила установщика (`InstallerScriptTests`), свойства
  файла продукта (`ProductMetadataTests`), документы репозитория и описание
  выпуска (`RepositoryDocsTests`), уязвимости в дереве пакетов и причина
  закреплённой версии ControlzEx (`DependencyAuditTests` и шаг CI
  на каждом прогоне), реальное обновление с предыдущего опубликованного
  инсталлятора и проверка Authenticode всех упакованных EXE.
